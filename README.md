# Workly

ממשק בעברית (RTL) שמקבל טקסט חופשי — בריף מלקוח, רשימת משימות, רשימת פגישות, או תערובת — ומארגן אותו לשלושה פלטים:
**בריף מקצועי**, **משימות מתועדפות** (היום / השבוע / חסומות / הושלם) ו**לוח פגישות**.

הכלל המרכזי: **כל ערך שמוצג כעובדה מגובה בציטוט מילה במילה מהטקסט**, והציטוט מאומת על ידי קוד ולא על ידי המודל.
מה שחסר או לא ברור הופך לשאלה ולא לניחוש. לחיצה על ערך מציגה את המקום שלו בטקסט המקורי, מודגש.

## הרצה

```bash
cp .env.example .env        # ולהוסיף OPENAI_API_KEY
docker compose up --build   # Postgres + שרת + ממשק
```

הממשק: <http://localhost:8080> (השרת גם ב-`localhost:4000`).

### בלי Docker (לפיתוח)

```bash
docker compose up -d db     # Postgres בלבד
cd backend  && npm install && npm start      # http://localhost:4000
cd frontend && npm install && npm run dev    # http://localhost:5173 (proxy אל /api)
```

בדיקות: `npm test` ב-`backend` וב-`frontend`.

## משתני סביבה

| משתנה | חובה | הערה |
|---|---|---|
| `OPENAI_API_KEY` | כן, לחילוץ | הדבר היחיד שצריך למלא ב-`.env`. המפתח לא נכנס ל-repo ולא ל-ZIP |

`PORT` (4000), `DATABASE_URL` (Postgres של ה-compose) ו-`OPENAI_MODEL` (`gpt-4.1-mini`) יש להם ברירת מחדל שעובדת, ולכן אין צורך להגדיר אותם.

## דמו — בלי "מצב דמו" מזויף

אין טבלת תוצאות מוכנות. בלי מפתח האפליקציה עולה, והבקשה הראשונה לחלץ טקסט חדש מחזירה בצ'אט הודעה ברורה שלא הוגדר מודל.

כדי להריץ את **טקסטי המטלה עצמם** (בריף, משימות, פגישות) דרך המערכת האמיתית והמודל האמיתי:

```bash
cd backend && npm run demo
```

הסקריפט (`backend/src/scripts/demo.ts`) שולח את שלושת הקבצים מ-`backend/samples/` לשרת הרץ בזה אחר זה, מדפיס כל שלב בעיבוד ואת התוצאה, ובסוף מדפיס קישור שפותח את אותו workspace בממשק.

## איזה מודל ולמה

`gpt-4.1-mini` עם Structured Outputs (סכמות Zod). המודל **רק קורא**: מחזיר ציטוטים, תאריכים ושעות *כפי שנכתבו*, ומילים שמסמנות דחיפות, תנאי או המתנה. הוא לא מחשב תאריך, לא קובע עדיפות ולא מתקן יום בשבוע.
זו משימת חילוץ ולא חשיבה, ולכן מודל קטן, מהיר וזול מספיק. את ההחלטות עושה קוד דטרמיניסטי שאפשר לבדוק בלי רשת (פרסור תאריכים ושעות, עדיפויות, חפיפות, מיזוג). כשהמודל מנסח מחדש ציטוט, האימות מזהה ולא נותן לזה להפוך לעובדה.

## תוספות מעבר למבוקש

- עריכה ידנית של תאריך/שעה/שדה בבריף (ערך שנערך גובר תמיד על מודל), הוספת משימה ידנית וסימון כבוצע (גם בגרירה)
- פתרון סתירה בין שני טקסטים בלחיצה (להשאיר / לעדכן)
- ייצוא פגישה או כל הפגישות ליומן בטלפון (`.ics`)
- בחירת תאריך ייחוס ידנית לטקסט הבא
- שמירה ב-Postgres: ה-workspace שורד הפעלה מחדש

## מה לא עובד / נשאר לביצוע

- פגישה שכתובה בתוך רשימת משימות (למשל "יש לי פגישת צוות ב-10:00") נחשבת משימה ולא נכנסת ללוח השנה, כדי לא להציג אותה פעמיים.
- כשהמודל מנסח מחדש ציטוט (קורה, למשל, ב"פרינט A4, דו-צדדי"), הערך מסומן "לא מאומת" ונוצרת שאלה במקום להסתיר.
- דדליין עמום ("לפני סוף השבוע") הופך לשאלה ולא נקבע לו תאריך.
- אין משתמשים או הרשאות: ה-workspace מזוהה לפי הדפדפן (localStorage) או קישור.
- הטיפוסים המשותפים משוכפלים בין `backend/src/types` ל-`frontend/src/types` (בדיקה ב-backend נכשלת אם הם סטו זה מזה: `npm run sync:types` בפרונט).
- הפרומפטים נבדקו מול המודל האמיתי דרך `npm run demo`, אבל אין בדיקות אוטומטיות שרצות מול המודל.
- אין בדיקות דפדפן אוטומטיות; הממשק נבדק ידנית.
- גרירה בין עמודות פועלת רק אל "הושלם" ובחזרה; שאר העמודות מחושבות מהטקסט.

## איך השתמשתי ב-AI בפיתוח

_(לערוך בקול שלך לפני ההגשה.)_ בניתי את הפרויקט עם Claude Code, בשיחה שבה הגדרתי את הארכיטקטורה ופרומפט עם כללי עבודה מפרויקט קודם (הפרדה בין "מי שקורא" ל"מי שבודק", camelCase, בדיקות מול ממשק `Extractor`). ה-AI כתב את רוב הקוד; אני קבעתי מבנה, בדקתי את התוצאות וקיבלתי החלטות (אין דמו מזויף, בלי חבילת `shared`, Postgres עם כתיבה אחרי הקריאה).
צריך היה לתקן אחריו: רגקס שקרא אותיות עבריות כ"לא-מילה" (`\W`) ולכן זיהה תאריך ייחוס בתוך משפט; כתיבת תווי escape שהפכו לתווים אמיתיים; שכחה של `\;` בייצוא ליומן שמצאתי ב-grep; פריסה שבה לוח השנה יצא מהמסך; ופרומפטים שהמודל נהג לפרש בחופשיות (כתב "היום" כתאריך למשימה שלא כתוב בה, וניסח מחדש ציטוטים) — כוונון אחרי ריצות אמיתיות.
