# backend

Node + Express + TypeScript. שתי חצאים שמופרדים בכוונה.

```
routes/        דק: router.method(path, controller) ותו לא
controllers/   קובץ לכל resource; כל handler עם try/catch ותשובה בצורה אחת: { ok, data | error }
agents/        החצי שקורא (LLM): פרומפט + סכמה לכל סוכן, מאחורי הממשק Extractor
pipeline/edits/    כל שינוי במצב, קובץ לכל ישות (משימה, פגישה, בריף, שאלות). כל פונקציה מחזירה { workspace, label }
pipeline/commands/ הוראות מהצ'אט: פרסור, מציאת פריט לפי מילים, הפעלה דרך edits/
pipeline/      החצי שבודק (קוד רגיל, נבדק בלי רשת): כל ההחלטות
services/      workspace.service — מצב בזיכרון + כתיבה ל-Postgres אחרי כל שינוי
db/            חיבור, schema.sql, שאילתות
types/         החוזה מול הפרונט (מועתק ל-frontend/src/types)
scripts/       demo.ts — מריץ את טקסטי המטלה דרך שרת רץ
```

## הפיפליין (`pipeline/runPipeline.ts`)

`normalize → זיהוי תאריך ייחוס → הוראות → סיווג קטעים → חילוץ (בריף + משימות + פגישות במקביל) → אימות → מיזוג → עדיפויות`

לראות את זה קורה על טקסט אמיתי: `npm run trace -- "הודעה" "עוד הודעה"` מדפיס לכל שלב מה נכנס אליו, מה המודל החזיר (גולמי) ומה הקוד עשה בזה.

- **חילוץ:** המודל מחזיר *סימנים* בלבד: ציטוטים, תאריכים ושעות כפי שנכתבו, מילות דחיפות/תנאי.
- **אימות:** `buildBrief` / `buildTasks` / `buildMeetings` מוצאים כל ציטוט בטקסט (`quoteMatching`), מחשבים תאריכים ושעות (`parseDate`, `parseTime`) ורק אז מסמנים `verified`. סימן שהציטוט שלו לא בטקסט נזרק.
- **הכרעה בין סוכנים (`dedupe.ts`):** שני סוכנים יכולים לתבוע אותו משפט. פגישה עם שעה עולה ללוח השנה והמשימה הכפולה נמחקת (אלא אם היא מוסיפה דחיפות או תנאי). "פגישה" בלי שעה שחופפת למשימה היא משימה שנקראה בטעות.
- **קישור משימה לפגישה (`linkMeetings.ts`):** "להכין חומרים לפגישה עם שגיא" נקשרת לפגישה אחת בלבד אם המילים מתאימות רק לה. משימה קשורה יורשת את התאריך והשעה של הפגישה כדדליין ומופיעה לפניה.
- **עדיפות:** `prioritize.ts`, כללים בסדר קבוע (חסומה, P1, P3, P2, P4), והכלל שהתקיים נשמר כדי שהממשק יסביר. שעה קשיחה יכולה להיות של המשימה או של הפגישה שהיא מכינה אליה.
- **מיזוג (`merge.ts`):** עובדה שכבר ידועה לא נדרסת; פער נמלא; שני ערכים שונים הופכים לסתירה (שאלה); ערך שנערך ידנית גובר תמיד.
- **`recompute.ts`:** כל מה שנגזר (עדיפויות, חפיפות, שאלות) מחושב מחדש אחרי כל שינוי, גם עריכה ידנית.

## שכבת שינוי אחת, שתי דלתות

`pipeline/edits/` היא המקום היחיד ששוכתב בו מצב. כרטיסייה מגיעה אליה דרך `routes → controllers`, והצ'אט דרך `agents/commands → pipeline/commands`. אחרי כל שינוי `recompute` מחשב מחדש עדיפויות, חפיפות ושאלות.
`services/workspace.service.ts → applyChange` הוא הדלת האחת לשמירה: מריץ את העריכה, רושם שורה ביומן, שומר snapshot לביטול (`services/history.ts`, עד 10) ורק אז כותב. עריכה שנכשלת לא נשמרת.

הוראות בצ'אט: הסוכן מחזיר סימנים (סוג פעולה, ציטוט, מילים שמזהות את הפריט, תאריך ושעה כפי שנכתבו). `parseCommand` מאמת ומפרסר, `findMatches` בוחר פריט רק אם יש התאמה ברורה אחת, `executeCommand` קורא לאותן פונקציות edits. משפט שטופל כהוראה מוסר מהטקסט שמגיע לסוכני הקריאה.

## למה `Extractor` הוא ממשק

כדי שבדיקות יזריקו תשובות קבועות ויריצו את כל הפיפליין באמת, בלי רשת ובלי מפתח (`tests/helpers.ts`). המימוש האמיתי: `agents/openai.extractor.ts`.

## שמירה

`workspace.service.ts` שומר בזיכרון ומשקף ל-Postgres אחרי כל שינוי; בעלייה הוא טוען הכל מהמסד. אומת מול Postgres אמיתי: כתיבה נוחתת, הפעלה מחדש טוענת, וה-API מחזיר את המצב שנשמר.
